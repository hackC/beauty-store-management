# V1.6.0-dev.8 账号、会话与权限规则组模块化报告

## 1. 本轮范围

在 dev.7 全站模块边界设计基础上，实际落地 `identity`、`authorization` 两个后端模块，并建立库存主站与每日排班共用的前端应用壳基础设施。保留 FastAPI 路由作为 HTTP 适配层，`main.py` 负责组合依赖和兼容门面，不再承载密码算法、会话持久化和权限组 CRUD SQL。

## 2. 新增模块

### identity

- `domain.py`：身份错误、登录结果、审计操作者值对象。
- `ports.py`：身份仓储、密码哈希、会话令牌、权限视图和时钟接口。
- `security.py`：PBKDF2-SHA256 密码哈希和会话令牌工厂；迭代次数及盐/哈希编码保持旧格式兼容。
- `sqlite.py`：账号查询、首次管理员创建、一次性激活码消费、会话创建/撤销、首次设密事务和审计的 SQLite 适配器。
- `service.py`：登录、首次登录、首次设密、会话解析、过期清理、退出、账号视图、员工创建/修改/停用、激活码重发及管理员重置密码等应用用例。
- `composition.py`：由入口注入数据库连接工厂和现有权限查询服务。

### authorization

- `domain.py`：授权管理错误与审计操作者值对象。
- `ports.py`：权限规则组仓储接口。
- `sqlite_groups.py`：规则组和成员 CRUD、事务、敏感操作审计的 SQLite 适配器。
- `service.py`：规则组创建/更新/删除、成员分配/移出、权限目录验证和停用模块历史授权保留。
- `composition.py`：在入口注入规则组仓储及 dev.6 权限策略服务。

## 3. 依赖方向

`identity.service` 不导入 FastAPI、SQLite 或 `main.py`；`authorization.service` 同样只依赖领域值和仓储接口。SQLite 只存在于适配器中。`main.py` 只负责组合具体实现、HTTP 状态转换、Cookie 及兼容入口。

## 4. 兼容行为

- 保留 `/api/auth/*`、`/api/users*`、`/api/permission-groups*` 原有路径及主要响应字段。
- 保留 `inventory_session` Cookie 名称、HttpOnly、SameSite Strict、HTTPS Secure 配置和 14 天有效期。
- 保留 PBKDF2-HMAC-SHA256 310,000 次迭代、32 位十六进制盐和 64 位十六进制摘要的既有存储格式。
- 一次性激活码仍为单次使用；消费激活码在 SQLite `BEGIN IMMEDIATE` 事务中比较旧盐/摘要并清空，避免并发重放。
- 首次设密保留当前会话并撤销同一账号其他待设密会话；审计与密码更新在同一事务提交。
- 多权限组仍按允许项并集即时生效；未知权限和普通组敏感权限仍拒绝。
- 更新权限组时继续保留当前未注册模块的历史授权值，但这些授权在模块未注册时不生效。
- 管理员仍不能加入普通权限组；组名冲突、缺失组/员工等 HTTP 状态保持既有语义。

## 5. 前端应用壳

新增 `static/app_shell.css` 和 `static/app_shell.js`，由库存主站和每日排班页面共同引用。当前提供安全区域、触控目标、键盘焦点、表格滚动区标记、可复用吸顶标题/吸底操作栏原语、Esc 关闭移动抽屉和无障碍消息区域。PC/手机页面仍保留各自布局和业务脚本；本轮不是全站页面视觉重构。

## 6. 数据库与风险

- 未新增数据库表、列、索引或 schema 迁移；schema 仍为 8。
- 没有合并、覆盖、初始化或修改源码归档中的两份数据库。
- 会话和权限组写入继续使用原有表与事务边界。
- 原 `apply_upgrade.ps1` 仍是历史 V1.4.0 → V1.5.0 开发脚本，不能用于 dev.7/dev.8 升级或生产部署；本轮没有把它包装成安全覆盖升级器。

## 7. 后续边界

用户 CRUD 的所有写入细节、激活码重发/管理员重置密码等仍有部分 SQL 位于 HTTP 入口，后续继续迁移至 identity 管理用例。全站细粒度 `module.action + scope` 目录仍是草案，dev.8 没有切换生产 API 的授权判定来源。库存、排班和报表业务模块尚未迁出 `main.py`。
